# M4 正式 worker 报文闭环

新增集成入口使用实际 DPDK net_ring、mbuf、runtime 和正式 worker，
由 M4 模板、配额、异步批量服务及软件 classifier 控制报文，不经过旧管理协议。
测试仅枚举两个人工 ring 端口并指定 `--no-pci`，不操作实体网卡或管理接口。

每套构建实际接收 224 包，其中 176 包逐字节转发、48 包策略丢弃。
步骤依次核对：

1. 无规则时正常转发
2. 两条创建只完成一条时仍使用完整旧快照，UDP 9000 继续转发
3. 创建全部完成后，9000 DROP、9001 ALLOW+MARK=42，COUNT 读回 32 包/2048 字节
4. 两条删除只完成一条时仍使用完整旧策略，DROP 和 MARK 均继续生效
5. 删除全部完成后恢复普通转发
6. 再次创建的第二次分配失败，完整补偿后无账本或 classifier 残留，报文继续转发

转发还检查 mbuf 的 MARK 标志及值，丢弃同时核对收发包数、字节数和策略丢弃数。
worker 停止并注销后缓冲池可用数回到初始值，两个 RX/TX ring 均为空，配额、模板及队列全部正常关闭。

## 真实 API 不支持证据

21.11 原生模板配置与创建明确返回版本不支持 `ENOTSUP`。
24.11 则实际调用公共接口，由真实 net_ring PMD 返回 `ENOSYS`；
模板输入使用原生编译器支持的 COUNT+DROP，避免因不支持的 ALLOW 在编译前提前退出。
失败后模板身份输出保持不变，未留下引用、实际句柄或模板额度。
这证明明确拒绝及清理，没有登记为原生硬件正向能力。

## 同源验收

系统 21.11.9 优化、私有 24.11.8 优化、21.11.9 ASan/UBSan 三套各 78/78 单测通过，
另有 76 项工具门禁、四步核心回归、六步 M3、四组设备事件及 31 组模拟通过。
每套再执行上述 224 包的新 M4 路径，三套合计 672 包，均无缓冲泄漏或 sanitizer 错误。
主程序、旧流量工具及新 M4 流量工具的实际 DPDK 动态库均核对，现代构建全部来自私有 24.11.8。
