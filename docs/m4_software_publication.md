# M4 软件整批发布基础

`dppd_software_backend_change_batch` 接受最多 64 条混合增删改。
创建要求 ID 不存在且 expected 为零，替换和删除要求精确旧版本；同批重复 ID、非法规则、
不支持动作和容量不足均在改动活跃状态前拒绝。
新版本必须大于精确旧版本，删除不能使用零或 ANY。

整批先复制私有快照，在副本清除所有被替换或删除的槽位，再创建新增版本。
满表可以复用本批腾出的空间。新版本 COUNT 归零，未修改版本保留共享计数器。
全部分配及匹配编译成功才一次发布指针；失败丢弃副本，旧规则、动作和计数保持原样。
这是真实软件 classifier 的批量入口，后续 M4 协调器使用它提交完整批次。
本轮未改变 M3 同步批量路径，也不把此入口单独登记为异步批量闭环。

模板库另增加协调器 pin：占有界借用池并保护模板身份，不消耗实际 flow 表容量。
因此准备、删除及补偿期间可以保留配置，实际流清除后模板也不会被其他调用者提前销毁。
普通 flow 引用和 pin 都必须精确归还，重复或旧凭据仍拒绝。

系统 21.11.9 优化、私有 24.11.8 优化、21.11.9 ASan/UBSan 各 77/77 单测通过，
另有 76 项工具门禁、四步核心回归、六步 M3、四组设备事件及 31 组模拟通过。
276 项源码摘要为 `8952006f4f8e194bdac2029c9c2c1cea8952f54bd2796b6905e73f471423ce7d`。
同源结果位于 `build/native-check/m4-publication-artifacts/`，实际 DPDK 动态库已核对。

测试逐一注入创建时五处、满表混合操作时四处分配失败，核对零前缀、原版本和 COUNT 保留，
并覆盖过期版本、满表腾位和全批删除。
一个实际 QSBR reader 在 1000 次两规则发布期间持续匹配，只允许完整旧表或完整新表的 MARK；
中间混合规则会产生第三种 MARK 或未匹配，均被断言拒绝。
pin 测试验证实际容量为一时仍可同时持有配置保护和实际流，归还实际流后继续保护模板。
