# C 代码排版与注释约定

项目自有 C 源码和头文件使用根目录的 `.clang-format`，统一使用 clang-format 14。
规则覆盖 `app/`、`include/`、`lib/`、`tests/`，不处理构建目录、外部 DPDK 源码和补丁上下文。

- 默认以 **120 列**为换行参考，表达式、赋值和参数能放在一行时不主动拆开
- 个别完整日志字符串可保留在 120–150 列，避免为了排版拆散可搜索的文字
- 使用 4 个空格缩进，函数参数续行再缩进 4 个空格，避免为了对齐参数占用过多行宽
- 函数左大括号独占一行，控制语句的大括号跟在条件之后
- 控制语句的主体单独一行，不把多条执行语句塞到一行
- 复杂多层条件优先写成清楚的分支，不为压缩行数牺牲可读性
- 保留头文件包含顺序，避免整理格式时改变宏定义的生效环境

例如，下面这个短表达式直接放在一行：

```c
return service->persistence_dirty ? persist_current_repository(service) : 0;
```

中文注释允许 `/** */` 和 `/* */`，已有注释不必只为样式互相转换。
说明尽量写清楚目的、前提、资源归谁管理和失败后的处理，不逐句复述代码。
注释结尾不加句号或逗号；较长说明按意思分行，不要求每个函数都写一段重复说明。

```c
/** 必须读满指定长度才接受记录，提前遇到文件末尾说明快照被截断 */
static int read_all(int fd, uint8_t *data, size_t length)
```

在仓库中执行下面的命令，默认检查不会改写文件，发现格式不符时返回非零退出码：

```bash
python3 scripts/format.py --check
python3 scripts/format.py --write
```

脚本依赖 Git 和 clang-format 14，不会自动安装或下载工具。
可以用 `CLANG_FORMAT` 环境变量或 `--clang-format /path/to/clang-format` 指定工具路径，
Windows 同样可以使用 Python 和 `clang-format.exe`。项目格式整理在 14.0.6 下验证。

调整排版或注释后运行格式检查和既有构建测试；涉及逻辑整理时，再核对对应行为测试。
此次整理额外对比了去除注释和空白后的 C 标记，除动作共享判定的等价分支展开外，
其余 96 个源码与头文件的标记序列保持一致；共享判定使用既有专门测试回归。
系统 DPDK 与独立 TAP 驱动两套构建各通过 30 项单测，共享判定相关测试也通过
AddressSanitizer/UBSan；格式脚本已验证只读检查、写回、重复运行和版本不符时的拒绝。
