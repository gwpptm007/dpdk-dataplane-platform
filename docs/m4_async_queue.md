# M4 有界异步 flow 生命周期

队列把受理、驱动入队、完成通知和结果领取分开。整批最多 64 条，先预留槽位、实际 flow 配额、
私有计数器配额与模板引用，全部成功才返回身份；提交阶段不调用驱动，失败撤回全部预留。
此接口管理实际对象，尚不发布 desired 账本；后续批量协调器须在完整批次成功后统一发布。
单条完成成功不能直接视为整批成功，当前不把生命周期库登记成 M4 批量闭环。

每队列深度最多 256，完成但未领取也继续占槽位和操作配额，防止消费者停顿导致内存无限增长。
多个生产者可并发提交，驱动回调在同一锁内串行；同一驱动上下文、端口和队列不能创建第二个消费者。
回调不能重入本队列。一个实例只管理自己创建的对象，不得与其他消费者分享驱动完成队列。

## 身份与失败

每个完成标签是进程内不复用的整数，驱动返回的 user_data 不被解引用。
完成按标签匹配，允许乱序；重复、陌生或错误队列的标签隔离队列，不消耗其他操作的配额。
flow 身份另有实例、槽位及序号，旧槽位凭据不能删除重用后的新对象。

创建返回句柄仅代表已受理，必须等待其创建完成才能提交销毁。
即使创建完成失败，已返回的句柄仍占实际额度和模板引用，必须经过销毁成功完成才释放。
销毁排队失败或完成失败都保留原对象，可按同一精确身份重试。
尚未发送的操作可取消；取消销毁会保留原对象，取消创建会撤销预留并返回取消结果。

push、pull 失败及超时只隔离并保留对象，不推断实际流不存在，也不提前允许删除仍在创建的对象。
暂态故障须收齐完成、领取所有结果并再次成功空拉取后才可恢复；
批量协调器接入后允许保留已知 READY 的已提交流，失败创建及未知流仍必须清理或隔离。
陌生完成或不合约句柄属于无法自行证明的实际状态，不能自行解除隔离或强行关闭；
需要端口外部清理及干净进程重启，不能凭超时或停止设备把残留当作已清除。

## 原生适配

24.11 调用实际 `rte_flow_async_create/destroy/push/pull`，使用 postpone 统一发送。
编译参数及其中的自引用指针保留在独立堆对象内，直到销毁成功完成后才释放包装内存。
共享绑定仍待后续接入，其他未支持的 IR 明确拒绝。21.11 原生异步接口返回 `ENOTSUP`。
配置端口和模板库的生命周期约束见 [模板文档](m4_templates.md)，不自动切换现有 M3 模式。
