# M4 队列完成延迟与规模

新基准测量正式 `dppd_flow_service` 从提交到完整批次发布并领取结果的延迟。
模板、逻辑/实际额度、异步队列、任务等待、乱序完成和整批账本均使用生产实现，
只有驱动换成明确命名的内存驱动，不测 ASIC 或实际软件 classifier 的报文吞吐。

每批 64 条、八个应用队列、每队列深度 256；每窗口先提交 32 个批次，共 2048 条，
使八个队列都达到完整应用深度，再开始消费。
每个批次的计时包含前面批次的等待，不能只测驱动回调或挑最后一段执行耗时。
每批确认完整账本回执，安装后逐项查询全部规则，最后整批删除所有对象并确认资源归零。

| 16384 | 256 | 4.857037 毫秒 | 34.576985 毫秒 |
