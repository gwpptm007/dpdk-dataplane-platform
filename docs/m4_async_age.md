# M4 队列 AGE 自动回收

M4 原生配置现在要求严格队列标志。24.11 先核对驱动支持，再配置严格队列及老化对象池，
不支持时在配置前明确拒绝。[DPDK 24.11 Flow API](https://doc.dpdk.org/api-24.11/rte__flow_8h.html)
规定非严格模式会忽略 AGE 查询的 queue_id；本实现使用严格模式，避免一个队列领走另一个队列的通知。
21.11 原生配置和队列 AGE 入口继续明确返回版本不支持。

创建时 AGE context 使用进程内不复用的整数标签，独立于驱动指针、请求栈和 flow 槽位。
队列查询只还原整数，不解引用任意 context；过期通知计入 stale，不删除同 ID 的新版本。
补偿可能重建同一 generation，因此还同时核对实际 flow 实例身份，不能只比较规则 ID 和版本。

## 周期、预算和维护任务

`dppd_flow_service_process` 在存在已发布 AGE 规则时自动轮询，默认间隔 100 毫秒。
每次按调用预算及队列实际深度取较小值，轮换队列和缓存游标，避免长期只处理第一个队列。
一次性通知缓存在精确 flow 上：创建尚未完成、尚未发布或正被其他批次使用时，留待后续处理。
创建完成前不能因为 AGE 通知提前销毁句柄。

每队列另有一个有界维护任务槽，最多携带一个批次，不增加实际驱动队列数量。
用户完成回执占满应用深度时，维护删除仍可执行；驱动操作仍受原队列深度及在途额度约束。
维护任务调用同一个精确版本批量删除及补偿流程，只有完整终态才自动领取内部结果。
成功释放逻辑额度、实际流、私有计数器、老化对象和模板引用；失败继续保留尚存在的实际状态。

查询失败保留规则和已有通知，记录独立查询错误，不把查询失败当成无老化流。
普通删除失败、完整恢复旧规则后退避一秒重试；补偿失败进入统一隔离并保留维护任务，
由显式 `retry` 精确恢复。软件驱动当前没有等价 AGE 动作，明确拒绝，不伪造硬件空闲时间。

## 老化对象额度

新增独立 `AGING_OBJECT` 全局/端口额度，与实际 flow 和私有 COUNT 一起在驱动前整批预留。
零额度禁止 AGE；失败完成、等待删除和补偿中的对象继续占用。
调用方须同时配置实际端口老化池和平台额度，平台账目不会替代真实 PMD 的资源能力检查。
原来的 64 项预留需求上限保持不变，资源类别现为九种，满批测试仍覆盖 64 个不同资源/端口项。

## 同源验收

系统 21.11.9 优化、私有 24.11.8 优化、21.11.9 ASan/UBSan 三套各 79/79 单测，
76 项工具门禁、四步核心回归、六步 M3、四组设备事件及 31 组模拟通过。
三套均重新执行新 M4 正式 worker 的 224 包闭环，实际动态库及源码逐项一致。
285 项源码摘要为 `9ecb678334e54d7461724db037fe2532b35f904ff2365b1f3b6dca0ba94cfbe7`。
证据位于 `build/native-check/m4-async-age-artifacts/`。

新增模拟驱动测试覆盖重复和迟到通知、创建完成前缓存、同版本补偿后的旧 context、
查询失败不删除、预算跨队列轮换、删除失败退避、维护回执自动回收及用户完成回执背压。
老化额度耗尽时驱动创建次数为零，清理后额度和引用归零。
24.11 包装入口检查严格队列配置、AGE context 有效期、真实队列 AGE 调用及输出错误保留。
这些是软件协调与 API 契约证据，实际硬件的老化触发时间、报文命中和共享引用仍需实机单列。

加入轮询后同源五轮队列完成 P99 中位数为 4.532802 毫秒，继续通过冻结的 100 毫秒门槛。
共享动作联动、异步更新和最终同源联合验收继续推进，整体 M4 尚未完成。
