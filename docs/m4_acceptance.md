# M4 软件交付与验收契约

本阶段按 [路线图](roadmap_v3.md) 实现 template table、async flow queue、资源配额、批量操作、
aged flow 回收、shared action、背压和 admission control，不扩展 M5，也不等待 M3 实机。
软件交付及当前环境整体验收已完成，完整结果见 [M4 软件整体验收](m4_final_acceptance.md)。
三套同源各 82/82 单测、完整十二步 TAP 和八项冻结性能门禁全部通过，硬件实机目标仍单列待验。

## 基线

基准复用正式 `dppd_control_apply/create_batch/remove`，没有复制一套假的事务或账本。
`memory_driver` 只替换 PMD 校验/创建/删除，测到的是控制面软件开销；`software` 使用正式软件后端。
故障恢复计时只测创建及补偿失败后的进程内残留清理，不包括 daemon 重启或物理设备复位。
P99 是完整 C 控制 API 的调用耗时，不含 Unix socket 编解码；队列完成 P99 将另行覆盖提交到完成的等待。

135 / DPDK 21.11.9 / GCC 11，`debugoptimized`、`werror=true`、断言开启，CPU 0–3，五次全部保留后取中位数：

| 路径 | 规模 | 批量 | 安装规则/秒 | 请求 P99 | 删除总耗时 |
| --- | --- | --- | --- | --- | --- |
| 内存驱动控制面 | 4096 | 1 | 87922.082 | 19.918 微秒 | 26.029 毫秒 |
| 内存驱动控制面 | 4096 | 64 | 89144.514 | 1.380 毫秒 | 25.955 毫秒 |
| 正式软件后端 | 1024 | 1 | 5074.085 | 521.573 微秒 | 194.321 毫秒 |

残留对象清理中位数为 290 纳秒，此值不是整机故障恢复时间。
优化构建首次发现三处时钟失败可能返回零的路径，先补齐非零错误返回再建立基线，
没有改变规则规划、事务、索引、后端或数据面的算法。
首轮 258 项源码摘要为 `9f2b50aa3928d755e12578c46ccbc3dcd9ffa7d6d4071a4133450c7984191d3f`。
原始五次输出和基准报告保存在 `build/native-check/m4-baseline-artifacts/`。

为使完整优化构建也通过严格检查，本轮还用独立 IPv6 结构暂存 CLI 地址，初始化流量夹具的出队指针，
补齐 libc 长度检查入口的身份夹具及内联时钟测试的游标重置，没有关闭告警、断言或失败场景。
最终 258 项源码摘要为 `2591ffd0bd8544f405d9881fc21e281d09caa100f5ed2bfeb0a3120fbffdf9a6`。
系统 21.11.9 优化构建、私有 24.11.8 优化构建与 21.11.9 ASan/UBSan 各 70/70 单测、
76 项硬件工具门禁、四步核心回归、六步 M3 和 31 组模拟通过，报告源码逐项一致。
现代主程序及两个真实流量工具的全部 DPDK 动态库均核对为私有 24.11.8，排除混链系统 21.11。

最终同源复测的五次中位数分别为 68790.978、66291.600、3772.246 条/秒，
请求 P99 分别为 28.876、1633.019、697.780 微秒，残留清理 571 纳秒。
这轮完整采集期间另有隔离构建运行，原始结果照实保留，不用更好的首轮数值替代它。
这些值尚未全部达到已固定的后续门槛；M4 需要继续优化，不能把基准采集成功写成性能目标完成。
本轮没有重复完整 TAP，已有 TAP 证据继续按其原始提交记录。

## 固定验收标准

[机器可读契约](m4_acceptance_contract.json) 的 revision 1 在 M4 功能实现前固定。
后续未达标应继续修复，不能根据已测结果降低门槛或移除失败轮次。
规则规模目标为 16384，模板表 64、队列 8、每队列深度 256、每批 64、共享对象 64。

| 指标 | 软件范围内的门槛 |
| --- | --- |
| 4096 条内存驱动单条安装 | 至少 70000 条/秒，保护既有基线 |
| 16384 条内存驱动单条安装 | 至少 100000 条/秒，单次 API P99 不超过 500 微秒 |
| 1024 条正式软件规则安装 | 至少 4000 条/秒，单次 API P99 不超过 1 毫秒 |
| 4096 条、64 条每批的队列完成 | 提交到完成的 P99 不超过 100 毫秒 |
| 进程内残留清理 | 不超过 50 毫秒 |
| 16384 条期望状态重放 | 不超过 5 秒，不包含硬件或操作系统重启 |

资源满、队满、重复/过期请求、分配失败、创建/删除/补偿失败、超时、乱序完成、并发与恢复均需独立证据。
残留对象、准备项和异步未完成对象仍持有配额、模板与共享引用，不能用提前释放换取表面吞吐。
全部原有功能测试必须通过，完整 TAP 与核心回归分别登记。

物理网卡安装速率、ASIC 容量、报文旁路和真实复位 RTO 单列待验收，软件或内存驱动结果不补成硬件通过。

## 重复采集

```sh
meson setup build-perf --buildtype=debugoptimized -Dtests=true -Dwerror=true -Db_ndebug=false
taskset -c 0-3 python3 scripts/benchmark_m4.py --build-dir build-perf
```

`benchmark_m4.py` 校验构建来源、严格选项、断言、全部轮次及前后源码一致性。
它只输出当前已实现路径的测量结果，不会把基线运行成功标记成完整 M4 通过。
