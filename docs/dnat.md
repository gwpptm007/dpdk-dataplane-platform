# IPv4 静态 DNAT 与端口转发

2026-10-17，静态 DNAT 已接入正式 daemon、连接跟踪、状态 ACL、路由、双向报文改写、
管理查询和重启流程。支持 IPv4 TCP/UDP 的地址映射、单端口转发和等长端口段转发，
可单独启用，也可与现有出站 SNAT 共存。整个 M2 仍未全部完成。

## 配置与示例

在已有 `--ports 0,1 --ipv4-routing /private/routes.bin --conntrack 8192` 后追加：

```sh
# 外口 1 的 TCP 公网 443 转给内口 0 的后端 8443
--dnat 1,0,tcp,203.0.113.9,443,10.10.0.9,8443
# UDP 端口段一一对应：40000 -> 8000，40001 -> 8001
--dnat 1,0,udp,203.0.113.9,40000-40001,10.10.0.9,8000-8001
# 整地址 DNAT：该协议的端口全部保持原值，需要 TCP 和 UDP 时分别声明
--dnat 1,0,tcp,203.0.113.10,any,10.10.0.10,same
--dnat 1,0,udp,203.0.113.10,any,10.10.0.10,same
```

每条参数依次为 `外口,内口,协议,公网地址,公网端口,后端地址,后端端口`。
可重复声明，最多 32 条；协议只接受 `tcp` 或 `udp`。数值端口为 1–65535，支持单值和
`A-B` 闭区间，两端范围必须等长，按偏移映射，不做取模或负载均衡。后端 `same` 表示
保留原端口，公网 `any` 必须配后端 `same`，其内部范围包含全部 16 位端口值。

两端地址必须是不同的有效单播 IPv4，内外口必须是已配置的两个不同端口。依赖显式
IPv4 路由和连接跟踪，不能在二层端口对模式里悄悄启用。配置校验拒绝：

- 同一外口、协议、公网地址上的重叠端口，包括完全重复的规则
- 同一内口、协议、后端地址上的重叠端口，避免相同客户端的回包无法区分公网身份
- 不等长、反向、溢出、空字段、未知协议、无效地址及超过数量上限的配置

不同协议可以使用相同公网端口；不同外口的同名服务也可配置，但后端身份必须能够
区分。规则 ID 按启动参数顺序从 1 分配，只在该进程配置中解释，不是跨部署的稳定 ID。

NAT 不替用户配置 Linux 地址、ARP 或外部路由。公网流量必须能够到达外口；后端的
回包必须经过同一实例，并有回到客户端的外口路由。内网目的路由必须指向声明的
内口，不能把公网目的地址的默认路由当作后端路由。此范围参考
[RFC 3022 的静态映射与双向路径说明](https://www.rfc-editor.org/rfc/rfc3022)，
不表示完整 NAT 行为或所有协议都已实现。

## 正反向身份与 ACL

例如客户端 `198.51.100.7:12345` 访问 `203.0.113.9:443`：

| 阶段 | 源地址和端口 | 目的地址和端口 |
| --- | --- | --- |
| 外口收到请求 | 198.51.100.7:12345 | 203.0.113.9:443 |
| ACL、路由和内口输出 | 198.51.100.7:12345 | 10.10.0.9:8443 |
| 内口收到回包、回包 ACL | 10.10.0.9:8443 | 198.51.100.7:12345 |
| 外口输出回包 | 203.0.113.9:443 | 198.51.100.7:12345 |

客户端源地址和端口保持不变。入站 ACL 使用转换后的后端地址和端口，回包 ACL 使用
后端原始源身份。无映射、坏校验和或非法握手可以被 INVALID 规则记录，但允许动作
不能将这些错误放行。TCP 仍验证 SYN、SYN/ACK、第三次 ACK 以及后续 FIN/RST，详细
状态语义沿用[连接跟踪](conntrack_nat.md)。

```sh
# 外口允许访问后端 8443，允许建连和后续请求
./build/dppctl acl-set 2101 1 0 10 tcp any 10.10.0.9/32 any 8443 allow count state:new,established
# 内口只允许已建立会话的后端回包
./build/dppctl acl-set 2102 0 0 10 tcp 10.10.0.9/32 any 8443 any allow count state:established
# 需要白名单时分别给两个入口加较低优先级的 IPv4 拒绝规则
```

映射本身不等于业务授权。未配置拒绝 ACL 时，合法且命中静态映射的新连接可以进入
后端。DNAT 独立模式仅接受命中静态服务的新流及既有会话，其他新 TCP/UDP 流返回
无映射；共存模式另外允许原有 SNAT 内口新建出站流。未命中的公网端口不会泄漏到
普通路由，错误入口和内网访问公网服务的 hairpin 请求会拒绝。

会话仍使用两个索引共享同一份状态。正向按客户端到公网服务及外口查找，反向按
后端到客户端及内口查找，来自不同 RX 队列的流量共用映射。会话只能从声明的内外口
转发，路由变更到其他口会拒绝，不重新绑定既有流。

只有校验、ACL、路由、邻居、出口和报文改写全部通过才提交会话。拒绝不刷新旧会话，
失败的新候选不占容量。沿用原有共享/间接/外部/多段 mbuf 复制保护、TTL 递减、MAC
改写和 TCP/UDP 校验和处理，UDP 零校验和保持为零。

## 与 SNAT 共存及资源回收

```sh
--snat 0,1,203.0.113.9,40000-40002
--dnat 1,0,udp,203.0.113.9,40000-40001,10.10.0.9,8000-8001
```

在此配置中，UDP 的 40000、40001 始终属于静态服务，动态 UDP 出站只能分配 40002。
TCP 与 UDP 各自保留端口，UDP 静态服务不占 TCP 池。若静态保留覆盖任一协议的整个
SNAT 池，启动直接拒绝，需要换公网地址或调整端口范围。

DNAT 会话只占连接跟踪容量，不从动态池借端口；取消、老化、清空 DNAT 会话都不能
解除静态保留。SNAT 会话回收也只释放自身占用的动态端口。静态服务的后端源端口在
没有会话时拒绝创建 SNAT 流，避免旧回包在过期或重启后变成一条新出站连接。因此
已发布的后端源端口只用于会话回包；整地址映射的后端不能再从这些端口主动建连。
任意方向都能主动建连的一对一静态 NAT 不是本阶段交付。

## 查询、配置与重启

```sh
./build/dppctl nat-status
./build/dppctl dnat-list
./build/dppctl dnat-list 4
./build/dppctl conntrack-list
```

本阶段管理协议为 v19，后续 [IPv6](ipv6.md) 扩展为 v20，daemon 和 CLI 必须配套。`nat-status` 返回 SNAT 开关及静态规则
数量；`dnat-list` 每页最多四条，返回配置 ID、内外口、协议和两端地址/端口段。游标
是上一页的 `next-id`，超过末尾返回空页；启动配置不可变，不借用会话 revision。
`conntrack-list` 显示 `kind=dnat` 和 `dnat-rule`，保留原始及转换五元组、状态和两向
计数。恢复隔离期间可读静态策略，但禁止清空会话。

策略沿用 SNAT 的启动配置方式，需由部署保存全部 `--dnat` 参数。运行中不支持增删
或修改静态规则，修改需要重启；没有新增管理写入或第二份 NAT 持久文件。规则和路由
快照照常重放，正常/异常重启都清空运行时会话和计数。相同启动参数会重新安装同一
静态策略，新连接可重新建立；旧 TCP 中途 ACK 及无会话的后端回包均拒绝。UDP 入站
请求无法仅凭五元组区分新旧，会按 NEW 重新建连，不承诺无损会话迁移。

```sh
meson test -C build --print-errorlogs
python3 tests/integration/ipv4_traffic.py --build-dir build
sudo python3 tests/integration/dnat_traffic.py --build-dir build
sudo python3 tests/integration/dnat_traffic.py --build-dir build-native
```

Ubuntu 22.04 / DPDK 21.11.9 的系统与原生 TAP 标识补丁构建均使用 `-Werror`，各
43/43 单测通过；七项相关 AddressSanitizer/UBSan 检查和单双队列验收通过。

单测覆盖配置上限、范围和冲突、双向映射、逻辑 ACL 身份、错误入口、候选取消、容量、
老化、分页、恢复隔离查询及静态保留。正式单双队列 worker 检查共享会话、双向完整
字节、共享原包不变及 mbuf 回收。三 TAP 的独立 DNAT 和 SNAT 共存场景独立重算报文
校验和，覆盖整地址、端口段两端、TCP 握手、UDP 零校验、VLAN、ACL 拒绝不刷新、
错误报文、无路由/邻居、出口错误、满表、端口池保留、清空、过期及崩溃重启。

测试只在自己新建的空网络命名空间创建和清理 TAP，不改变实体接口。IPv6 解析/ACL/转发已在[后续阶段](ipv6.md)接通，IPv6 NAT、ICMP/
RELATED 转换、分片重组、hairpin、ALG、动态后端和负载均衡、运行时策略更新、会话
复制和硬件有状态卸载未实现，不能按整个 M2 完成计算。
