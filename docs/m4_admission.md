# M4 全局与端口资源预留

本组件在真正调用驱动前，为一整批请求预留足够资源。
它管理的是平台自己的资源账目，不通过猜测网卡剩余容量来替代 PMD 校验。
实现位于 `include/dppd/admission.h` 和 `lib/control/admission.c`。

## 如何计费

逻辑规则、硬件流、软件规则、模板表、共享动作、流队列、在途操作、计数器和老化对象分别设额度。
每种资源都有全局额度，也可按实际 DPDK 端口设置额度。
指定端口的请求同时扣全局与端口额度；显式 GLOBAL_PORT 请求只扣全局额度。
零额度表示禁止，最大整数也必须经过求和和剩余额度检查。
老化对象额度在 [M4 队列 AGE](m4_async_age.md) 中接入，未配置时不允许新 AGE 请求。

一次最多包含 64 项需求。重复的端口/资源项先合并，再整体校验。
后一项不合法、全局不足、某端口超额、求和溢出或凭据池已满时，整批均不占用资源。
返回值分别保留 `EINVAL/ENOENT`、`ENOSPC`、`EDQUOT` 和 `EOVERFLOW`，上层据此决定拒绝或背压重试。
失败只增加诊断拒绝计数，不填写输出凭据，也不增加任何资源占用。

## 预留、提交与残留

预留成功后得到带有实例、连续编号和槽位的凭据。即使槽位已经复用，旧凭据也不能操作新对象。
别的分配器实例收到同样槽位/编号也会拒绝，实例编号和凭据编号均不允许回绕。
凭据槽位在初始化时一次分配，预留、提交和释放路径不再申请堆内存。

提交只是将预留移到账本的已提交部分，总占用不变，不会在两个阶段之间空出额度。
重复提交返回 `EALREADY`。普通释放仅供取消未提交请求，或在上层已确认实际对象清理成功后使用。
删除、创建或补偿结果不确定时，将凭据标成 residual，原有额度继续占用。
重复标记不会重复计费，普通提交/释放均返回 `EUCLEAN`。
只有上层拿到确切清理结果后，才可调用 `release_recovered`；时钟超时、停止端口或设备失联均不是清理证明。

这些凭据只用于当前进程，不写入快照，也不代表重启后旧硬件对象已经消失。
仍有预留、已提交或残留凭据时，关闭组件返回 `EBUSY`，不会丢弃占用账目。
关闭前必须先停止所有调用者，关闭与使用者继续访问同一指针不属于支持的并发模式。

## 并发和动态额度

一次预检、扣额、凭据分配在同一互斥区完成，没有先检查、解锁、再扣额的竞争窗口。
状态读取也持有同一把锁，调用者不会读到移动到一半的预留/提交数量。
调整额度需要精确配置修订号，旧修订号返回 `ESTALE`。
不能低于当前预留和提交的总量，也不能借修改额度更换端口集合或凭据池大小。
所有检查完成后才一起更新额度和修订号，拒绝缩额不会留下部分修改。

## 当前集成边界

本轮交付可供 M4 模板、队列和共享对象使用的线程安全基础接口。
旧 M3 单规则和旧四条管理批量接口尚未自动接入这些新配额，不能据此宣称所有请求已经经过 M4 admission。
后续 M4 入口必须根据实际生命周期声明完整需求，并在驱动完成、删除确认和恢复时释放对应凭据。
本组件不创建网卡流、模板、共享对象或软件规则，也不证明真实驱动支持异步 API。

## 验证范围

`test_admission` 覆盖整批重复项、跨端口合计、多种资源、全局/端口/凭据池耗尽、
非法输入、两处初始化分配失败、最大整数与溢出、64 项完整需求、重复/跨实例/复用旧凭据、
预留及提交阶段的残留、精确恢复、缩额拒绝和配置版本竞争。
八个真实线程同时争抢四份额度，停在屏障处确认恰好四份预留和四次拒绝，
再持续争抢、提交、读取一致快照和释放，最后逐项确认所有资源归零。
