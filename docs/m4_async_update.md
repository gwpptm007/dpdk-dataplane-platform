# M4 异步批量更新

`dppd_flow_service_update` 接受最多 64 个精确旧 generation 与替换规则。
受理时复制完整输入，锁定旧版本，预留新模板及共享引用，继续复用原逻辑规则额度。
过期版本、重复 ID、队满、模板错误和准备失败不会调用驱动，也不会修改输出任务身份。

控制消费者先创建全部新 flow 并收齐创建回执，再在原队列删除全部旧 flow。
全部完成后，正式软件 classifier 一次发布完整替换快照，再由不分配内存的 repository
整批推进连续 generation。新版本私有 COUNT 归零，无关规则的 COUNT 保持；共享 COUNT 累计不清零。
逻辑满表可以更新，实际流、模板、计数器、AGE 池及引用池须保留临时容量；不足时明确拒绝并保留旧规则。

创建失败先清理全部新 flow；旧流删除失败或软件发布失败时，先清理新 flow，
再按原队列、模板及精确旧版本补回缺失旧 flow。旧模板和共享 pin 在整个补偿期间保持，
不因实际旧句柄已删除就提前释放。补偿失败保留任务、配额、凭据及引用，隔离后显式重试。
未知发布状态继续封闭，不能用普通重试假装一致。硬件重建可能重置私有历史计数，
本接口保证期望账本整批发布，不承诺硬件逐包原子切换。

## 同源验收

正式服务测试覆盖满逻辑表和满 classifier 的 64 条跨队列更新、连续新版本、加权背压、取消、
过期版本、重复 ID、任务分配失败、驱动前实际额度不足、受理后超时，以及八线程竞争同一旧版本。
不同阶段分别注入新建失败、旧流删除失败、软件发布分配失败、新流清理失败和旧流恢复失败。
补偿残留期间旧账本仍可查询，精确重试后资源回到已提交状态。

24.11 原生契约测试把 64 条规则从共享计数器 B 改绑到 A，保留 B 的累计值，
随后由 AGE 释放 A 的流引用，物理计数器始终只使用两个额度。
正式 worker 的真实 net_ring 报文在等待更新时命中完整旧策略，成功后命中新策略；
软件发布失败保留旧 COUNT，成功更新验证新版本 COUNT 归零后重新累计。
