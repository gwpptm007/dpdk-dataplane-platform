# M4 异步批量协调器

`dppd_flow_service` 把模板、全局/端口配额、异步实际对象、期望账本和正式软件 classifier 接通。
它是独立的生产 C 接口，不自动替换旧 daemon 的同步管理协议，不与旧控制面同时写同一 classifier。
创建时接管空队列，阻止第二个服务接管或关闭这些队列；所有依赖必须晚于服务关闭。

软件模式使用正式软件准备队列及 `dppd_software_backend_change_batch`，只有整批成功才一次发布 classifier。
原生模式使用已配置的真实异步队列和模板，不自动改变设备模式或降级到软件。
端口配置、独占生命周期及原生能力约束仍遵守 [模板](m4_templates.md) 和 [队列](m4_async_queue.md) 契约。
内存驱动、原生适配契约及实际硬件证据继续分别登记。

## 提交、完成与账本

多生产者提交时复制完整批次，最多 64 条；先保护模板身份并取得逻辑规则额度。
实际 flow、私有计数器和驱动操作额度在驱动调用前再整批预留，失败全部撤回。
受理不保证安装成功：后续容量竞争或驱动拒绝通过完整任务结果返回，不能把受理回执当成安装结果。

最多八个应用队列，各自按规则数计算有界深度；64 条批次消耗 64 个位置。
结果完成但未领取也继续占深度。单个控制消费者按受理顺序处理完整批次，
保持连续版本和账本顺序；批次内部的驱动完成仍可乱序。
`process` 每个驱动队列最多发送及拉取指定预算，不等待硬件完成。

创建时先收齐全部完成，再提交软件完整快照和无分配的整批账本。
任一条创建失败就清理本批全部已取得句柄，清理完成之前不产生失败终态回执，也不发布成功前缀。
准备中、失败完成和补偿中的对象都继续保留实际额度、逻辑额度及模板引用。

批量删除先锁定精确旧版本，实际对象全部清除后才整批移除账本。
中途失败会按原队列、原模板和原版本重建已删除对象；硬件历史 COUNT 不承诺恢复。
软件删除先在私有副本完成准备，分配失败仍保留活跃旧快照，因此此类恢复不清空旧软件 COUNT。
后续已增加 [64 条异步批量更新](m4_async_update.md)、[共享 COUNT 联动](m4_shared_count.md)
及 [队列 AGE 自动回收](m4_async_age.md)；本页后面的单测数量保留首次独立交付的历史记录。

硬件逐条创建/删除存在报文可见的过渡，不承诺硬件逐包原子；软件 classifier 的整批切换只发布一次指针。

## 失败与恢复

未激活的批次可以完整取消；排队超时尚未调用驱动时直接撤销。
已经激活的超时保留实际状态，继续收取精确完成后才清理，不能提前销毁正在创建的句柄。
补偿失败保留任务、版本、原模板和全部尚未释放的额度，隔离并拒绝新提交。
`collect` 对此返回 `EUCLEAN` 且保留任务；`retry` 重试已知补偿，清理完成后再核对并解除隔离。
最终回执只在完整终态后领取，旧任务凭据不能领取复用槽位中的新结果。

暂态队列错误在收齐完成、成功空拉取且所有保留流均为已知 READY 后可恢复，
不必删除无关的已提交规则。失败完成的创建句柄仍必须清理，陌生完成不能自行解除。
账本发布遇到不应出现的内部异常时保留隔离，不用普通重试冒充期望与实际已经重新一致。
当前不提供 M4 模板/队列的独立磁盘格式或自动端口复位，未知实际状态须外部清理后干净重启。

同源完整结果及实际动态库核对保存在 `build/native-check/m4-service-artifacts/`。

新增协调器测试使用正式软件队列与实际 classifier，验证 64 条完整创建、八队列接管、
MARK/COUNT/DROP 匹配、64 条删除、受理前后两种资源耗尽、完成未领取背压、重复所有者、
配置 pin、创建及发布分配失败、部分删除恢复、创建补偿失败和恢复补偿失败的精确重试。

超时测试保留无关已提交规则并最终恢复；六处构造分配故障和账本版本边界也已覆盖。
这些结果不代替新路径的整套报文字节集成或固定队列 P99 性能验收，后续继续收尾。
