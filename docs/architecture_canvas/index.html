平台职责

接受网络意图，维护版本化状态，按设备能力选择执行位置，并保证失败可恢复。

三份事实

Desired 是目标，Planned 是执行方案，Actual 是已观测现实。

硬件语义

rte_flow 与 embedded-switch rule 是控制面创建的对象，不是 worker 的逐包 stage。

持续收敛

设备重置、热插拔、规则老化或进程恢复后，由 Reconciler 重建一致状态。

明确排除

不把 PMD 调用泄漏到上层，不承诺所有策略都能卸载，也不伪装“软硬件逐包 fallback”。

线程模型

每个 RX queue 只有一个 owner lcore，run-to-completion 避免跨核共享包处理状态。

一致性边界

worker 在 burst 边界观察 generation；同一个 packet 始终使用同一 snapshot。

解析原则

可观测

热路径禁区

RPC、日志格式化、设备探测、rte_flow create、动态内存和控制面锁。

D17 成为新的 Desired，但此时数据面仍执行 A16。

2 · 候选分支

触发方式

事件触发负责低延迟，周期扫描负责兜底；二者最终进入同一去重队列。

修复粒度

以 resource dependency graph 计算最小差异，避免全量 flush 造成数据面抖动。

重试策略

无法修复

DETAIL A · MODEL CONTRACT稳定对象，而非运行时句柄
主键规则

resource_id 跨进程重启和设备重枚举保持稳定；port id、指针和 flow handle 只能作为 Status 中的引用。

Spec 与 Status 分离

Spec 表达用户目标；Status 只记录平台已观测到的结果，不能反向篡改策略。

依赖顺序

Attachment 依赖 Endpoint 和 Topology；Rule 依赖 Policy 与 Attachment；Backend Object 依赖 Plan Artifact。

可追溯性

每个 native object 都要能回溯到 resource、generation、transaction 和 planner decision。

删除语义

删除先标记目标不存在，再反向释放依赖；Actual 清理由 Transaction 和 Reconciler 确认完成。

DETAIL C · TRANSACTION ENGINE一个明确的提交边界
Admission

检查 if-generation-match、租户配额、依赖健康度与资源锁；避免无效事务进入执行阶段。

Prepare

只在全部 participant 具备可提交条件后进入 Prepared；worker 与外部读者仍看见上一稳定 generation。

Commit 顺序

按 Plan DAG 顺序创建底层对象，最后发布控制状态和软件 snapshot；删除遵循反向依赖顺序。

补偿不是回到过去

补偿尽力恢复安全状态；设备不可逆或外部变化时保留事实，交给 Reconciler 收敛。

错误契约

必须返回 phase / resource / backend / native reason / retryability / operation_id。

DETAIL D · RECONCILIATION LOOP持续验证，而非一次性成功
队列键

以 resource_id 去重，同一资源只保留最新目标 generation 和最高优先级触发原因。

反熵扫描

即使设备事件丢失，也会定期读回实际规则、counter、端口健康度和 worker snapshot。

最小差异

优先修复缺失或过期的单个对象；只有拓扑或能力变化时才要求重新规划整个资源图。

风暴控制

按资源、设备、租户做 rate limit 与 backoff；重复失败触发 circuit breaker 和告警。

最终状态

Blocked 不是删除 Desired；它是可解释的目标未满足状态，等待设备、容量或用户策略改变。
