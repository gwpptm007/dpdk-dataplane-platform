# M3 当前可落地范围与验收

本轮按 [路线图](roadmap_v3.md) 推进 SmartNIC/DPU transfer，先核查硬件，再完成当前
虚拟环境可验证的控制基础。整个 M3 尚未完成，不能用模拟结果代替实机卸载验收。

## 已交付范围

| 路线图项目 | 本轮实现与证据 | 尚缺证据或功能 |
| --- | --- | --- |
| 环境与设备 | 标准库只读盘点、权限/缺失保留、管理口识别 | 当前环境没有已验证的 mlx5/BlueField 实机 |
| representor 角色 | mlx5 严格名称解析、netlink/sysfs/PCI 交叉核对，未知保留来源与错误 | 实际 PF/VF/SF 与跨控制器设备验证 |
| 非 mlx5 适配 | 通用 PCI/非零 ifindex 身份；sfc/bnxt 有显式 PCI-only basic pair 工具，保留 UNKNOWN | 其他无宿主接口目标及六个命名模板仍需适配；AGE/共享/复位不得绕过 PMD 限制，实机未验收 |
| 同域与场景图 | 七种单向/双向模板、同域/别名/父子证据检查 | PMD 对具体匹配和动作组合的支持 |
| 正式控制入口 | v27 的 plan/apply、共享对象管理、精确全局版本、整批创建/补偿、隔离和持久化复用；设备状态与全组主动复位 | 无硬件逐包原子承诺；复位依赖真实 PMD 支持 |
| counter | transfer 方向契约、COUNT 64 位值及有效位检查 | 实机线缆报文与计数、CPU worker 对照 |
| AGE | 超时 IR、驱动独立查询、正式轮询与精确删除、v4/v5 快照和故障重试 | 真实 PMD 的闲置、命中续期及资源回收验收；事件通知未实现 |
| indirect/shared COUNT | 精确身份、引用保护、独立查询、v5 单快照及 v7 对象/引用恢复日志 | 实机未验收，TAP 原生/监护组合和其他共享动作未实现 |
| 移除/复位 | 正式 RESET/RMV/DESTROY 事件隔离、旧句柄保留、拓扑重发现、完整组主动复位与共享先行重建；独立模拟仍保留 | 实机 reset/端点移除后的 reconciliation；未知旧句柄须外部核对；软件与三层联合恢复 |

角色与图的使用方法见 [M3 控制闭环](m3_transfer.md)，适配器修复见
[驱动契约](m3_flow_contract.md)，实际设备观察见 [环境记录](m3_environment_20261018.md)。
通用身份语义见 [PCI 与接口核对](m3_generic_identity.md)，DPDK 21.11.9 的具体驱动缺口见
[PMD 能力矩阵](m3_pmd_capabilities_21_11.md)。mlx5 的端口动作支持不能代替源端口匹配项支持。
纯名称解析只证明语法；正式控制面使用经过发现核对的拓扑，测试夹具仅构造模拟证据。

## 验收分层

- 单测用可控驱动接口覆盖七种模板的正向安装、COUNT、验证/创建失败、补偿失败及隔离
- AGE 覆盖独立查询、闲置轮询、精确版本删除、失败重试、v4 快照和模拟命中续期
- 共享 COUNT 覆盖双向汇总、prepare/残留引用、AGE 释放、范围/版本拒绝及 v5 对象先行重放
- 复位模拟覆盖旧句柄失效、内存计划与快照不变、身份拒绝、共享及规则重建、补偿失败和显式恢复重试
- 正式设备单测覆盖回调/收发门禁、后端隔离、端口与管理身份核对、全组复位顺序、补偿和重试
- 正式 daemon 的正常/RESET/RMV/DESTROY 四组检查保留旧对象、拒绝操作、快照不变及重启日志保护
- 拓扑单测覆盖严格名称、权限/缺失、命名空间不一致、接口变化和文件描述符回收
- 正式 daemon/CLI 在 net_ring 上覆盖未知角色和交换域的明确拒绝、无副作用、版本与重启
- M2 回归覆盖现有软件 worker、双栈 ACL/NAT/ND/隧道及真实内核 TAP 的收发
- 硬件层必须另有设备、固件、拓扑、线缆流量、PMD 计数和 CPU 旁路记录，当前未执行

这里的 TAP 是实际内核虚拟接口，模拟驱动入口是单测夹具，两者均不是 mlx5 硬件。
不安装假的 SmartNIC backend 到生产路径，也不把 transfer 规则静默降级到软件执行。

## 重复运行

先按 [构建说明](build_and_run.md) 准备 Linux DPDK，开启 `tests=true`、`werror=true`。

```sh
python3 scripts/verify_m3.py --build-dir build
sudo python3 scripts/verify_m3.py --build-dir build --tap
sudo env LD_LIBRARY_PATH=/path/to/native/lib:/path/to/native/pmds \
  python3 scripts/verify_m3.py --build-dir build-native --tap
ASAN_OPTIONS=detect_leaks=0:abort_on_error=1 UBSAN_OPTIONS=halt_on_error=1 \
  python3 scripts/verify_m3.py --build-dir build-asan
```

统一入口只读盘点、调用 M2 回归入口执行全量单测与软件验收，再运行 M3 正式进程
拒绝、共享恢复保护、正式设备事件隔离和独立功能模拟。`--tap` 只在脚本新建的私有网络命名空间使用自己的 TAP，不修改实体设备。
没有 `--tap` 只执行核心软件回归，报告不会标记完整 M2 TAP 验收通过。

构建目录的 `m3-acceptance/` 保存日志和 JSON；`success=true` 只表示所列虚拟范围通过。
`hardware_acceptance=not_run` 和 `complete_m3_validation=false` 始终保留，M3 实机验收
不会由这条命令自动补成成功。失败、超时、单测跳过、旧子报告或源码中途变化均阻断成功。
软件回归由子入口按每一步限时并清理同组进程，M3 外层不再叠加总期限，避免提前
杀掉负责清理的父进程而留下内层测试或 daemon。其他 M3 步骤仍有各自的超时保护。
ASan/UBSan 本轮关闭 LeakSanitizer，实际 mbuf 归还由 worker 的内存池记录另行核对。

## 通用身份核对轮次

[通用 PCI 身份](m3_generic_identity.md) 已支持非 mlx5 的非零 ifindex 核对，角色保持 UNKNOWN。
基础核对失败不发布接口字段，物理名称可以双边缺失，权限、半截读取和名称变化不能作为缺失放行。
硬件工具分别核对 parent PCI 与完整 ethdev 名，允许 UNKNOWN pair，六个命名模板仍严格要求可信角色。

四套同版本各 70/70 单测，其中各含 68 项硬件门禁；六步 M3、五组共享恢复、四组正式事件和

135 ASan/UBSan 与 134 GCC 13 各四步核心回归通过。两机硬件预检仍为 blocked，
报告 schema 和工具源码摘要核对通过。无宿主接口的目标适配、非 mlx5 角色来源和实机证据仍缺。

## 复位模拟轮次（历史）

实现提交 `03dc2e9` 的源码相同。两套完整验收分别限制在 CPU 0–3 和 4–7 并行执行。

## 后续验收条件

AGE 接入前已补充 [可直接运行的功能模拟](m3_simulation.md) 和 [134 工具环境](m3_simulation_environment.md)。
独立模拟服务复用正式管理、事务和持久化，支持真实 CLI 与报文字节的正向演练；
统一入口增加 `transfer_simulation` 步骤。135 系统/ASan 与 134 新 GCC 13 环境各 55/55
单测、核心 worker、正式拒绝路径和十组正向模拟全部通过，报告对应同一 224 文件源码。
这是上述 222 文件基础验收之后的功能模拟扩展；完整 TAP 结果仍按基础实现版本登记，
新扩展的完整记录和摘要见 [功能模拟验收](m3_simulation.md)。

需要至少一套可使用的 NVIDIA mlx5/BlueField 和一套物理非 mlx5 PMD 环境，明确哪些
端口是管理口、哪些属于同一 embedded switch，再由实际 PMD 验证规则能力。
AGE、首期共享 COUNT、独立复位恢复模拟以及正式设备事件隔离与主动复位路径已接通，
仍须在真实 PMD 上验收 AGE、共享 COUNT、线缆流量、CPU 旁路和移除/复位恢复。
共享 RSS/METER/AGE 和 indirect 更新尚未实现，原始 M3 并未逐项要求这些动作，
不据此扩大本轮完成门槛；规模化共享动作扩展归后续路线图安排。
驱动、rdma-core、DPDK mlx5 PMD 可以安装，但不会凭软件产生 PCI 网卡或交换芯片；
可继续使用当前虚拟环境开发和回归，实机报告保持单独待验收。
