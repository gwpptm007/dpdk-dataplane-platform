# M3 共享 COUNT 异常退出保护

共享计数器和引用它的规则现已接入正式 daemon 的 `--recovery-path` 日志。
创建前先同步意图，之后才调用 PMD；创建结果和删除结果也分别同步。
快照保存期望配置，恢复日志保存可能残留的设备对象线索，两者用途不同。
这里解决的是异常退出后的保守保护，不承诺真实 ASIC 残留已经自动清理。

## 对象与引用

v7 日志区分 `flow` 与 `shared-count`，即使业务 ID 相同也不会混为同一个对象。
共享记录保存对象 ID、精确 generation、安装端口和 ingress/egress/transfer 域。
引用规则同时保存共享 ID 和 generation，不保存进程指针或容易失真的运行时引用数。

规则引用只接受日志中同安装口、同域和同版本的最新共享创建成功记录。
更新的意图、失败或删除记录会阻止借用旧的成功记录；多个未删除的成功记录也按歧义拒绝。
尝试编号单调增加，已确认删除的槽位可以复用，因此记录数组顺序不代表调用时间。

后端要求规则和共享对象的创建前、创建后、删除后三组回调完整配置，缺一组就拒绝共享操作。
正常退出先删除所有引用规则，再销毁共享计数器；实际删除成功后才释放句柄和引用。
日志写入失败不妨碍使用仍有效的真实句柄清理，但会锁存不确定状态，不能自动确认干净。

## 失败与崩溃

| 发生位置 | 处理结果 |
| --- | --- |
| 创建意图写入或同步失败 | 不调用 PMD，保留故障状态 |
| PMD 成功，创建结果保存失败 | 保留实际句柄和尝试编号，返回 EUCLEAN 并进入控制面隔离 |
| PMD 报错但留下句柄 | 保留不确定对象用于删除，不能再被规则引用 |
| PMD 报错且没有句柄 | 保存 CREATE_FAILED，不能仅凭空仓库确认没有残留 |
| PMD 成功却不给句柄 | 保留不确定槽位并隔离，无法安全删除时需要外部核对 |
| PMD 删除失败 | 保留原句柄和引用，允许之后重试 |
| PMD 删除成功但日志失败 | 释放已删除对象，不重复销毁失效句柄；日志仍要求外部核对 |
| 意图或创建结果之后进程被强制结束 | 下次启动在队列配置和快照重放前拒绝，等待明确的外部清理确认 |

失败创建没有取得句柄时，即使之后同版本重试成功并正常删除，也不能顺便抹掉旧失败线索。
待核对的记录与规则共用 256 个尝试槽位，记录满时拒绝新安装，不覆盖可能残留的对象。

## 兼容与清理边界

加载器继续接受 v1–v6，首次涉及共享对象时升级为 v7；旧 FLOW 的方向保留 unknown。
v7 将“需要 TAP 监护”保存为独立特性，普通 mlx5 日志不会因为版本变大而错误要求 TAP 监护。
已有 v6 的监护要求在升级、正常清理或外部确认后继续保留，不能借升级解除部署约束。

TAP 原生 cookie 和独立监护模式仍不支持 indirect，共享操作在 PMD 调用前明确返回 ENOTSUP。
这类模式依赖可读回的独立 TC 动作，不能将同样的所有权证明套到共享对象上。

`dppd-recovery show` 输出 first-kind、对象种类、域和精确共享引用。
`inspect/plan` 不会凭 TC 列表或相似坐标推断共享计数器不存在，未删除共享对象明确报告
`indirect-object-requires-external-cleanup`，共享引用规则报告
`shared-reference-requires-external-cleanup`，均不产生自动 TAP 删除候选。

DPDK 没有可移植的“进程重启后按旧指针找回 indirect 对象”接口。
必须先由设备和运维流程确认实际清理完成，再使用现有精确 revision 的
`acknowledge-clean ... --external-cleanup-complete`。
该命令只确认已经完成的外部清理，不会清空网卡，也不是自动修复命令。

## 验收与重复运行

```sh
python3 scripts/verify_m3.py --build-dir build
python3 tests/integration/m3_shared_recovery.py --build-dir build
```

统一入口增加 `shared_recovery`，本轮五步为环境盘点、四步核心软件回归、正式 transfer
拒绝、共享恢复保护和独立功能模拟。专用集成库只在测试进程通过 LD_PRELOAD 加载，
对象仅存在于进程堆内存，正式 daemon、CLI、日志、文件锁、工作线程和快照仍使用生产实现。
测试库不安装或链接到正式程序，不能作为硬件共享动作或 ASIC 清理证据。

单测覆盖 v1–v6 兼容、CRC 正确但语义错误、未知特性位、精确引用、重复身份、低槽位复用、
fork 崩溃窗口及 pwrite/pwrite64/fsync 故障。后端测试覆盖一对多引用、失败后同版本重试、
部分成功、无句柄异常、删除重试及按依赖顺序清理。正式进程覆盖正常清理、SIGKILL 后
拒绝重启、外部确认后的精确快照重放、未确认失败创建和离线清理拒绝。
